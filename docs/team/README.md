# 三人分工与协作约定

A 负责动作头，B 负责动作序列，C 负责评估。三条线从现有单步 Transformer 扩散基准独立启动，按照[实验协议](../experiments/protocol.md)和[接口约定](../design/interfaces.md)交付。

| 成员 | 研究与实验 | 专属目录 | 交付 |
| --- | --- | --- | --- |
| [A](member_a.md) | A0–A3：扩散/回归、MLP/Transformer、条件注入 | `src/course_heads/`、`configs/course/a/`、`scripts/course_train/a/` | 训练入口、checkpoint、离线指标、方法章节 |
| [B](member_b.md) | B1–B4：H、动作注意力、E | `src/course_sequence/`、`configs/course/b/`、`scripts/course_train/b/` | 连续性审计、序列训练与执行、checkpoint、方法章节 |
| [C](member_c.md) | C0 参考基线、正式评估、统计与作图 | `evaluation/course/`、`configs/course/eval/` | 任务清单、评估入口、结果汇总、统计、演示 |

目录初始只放接口和任务说明，不包含假实现。A/B 的独立训练入口可以调用已有公共模块；共享源码变更应作为小型独立提交，先通知对应接口维护者。

## 公共模块归属

| 公共部分 | 维护者 | 协作规则 |
| --- | --- | --- |
| 模型加载与 checkpoint 扩展 | A | B 提供新类型及 schema，A 集成加载注册 |
| 序列数据和滚动动作执行 | B | 保留现有 H=1 路径，执行变化交 C 核对协议 |
| 评测任务、指标定义和统计 | C | A/B 不自行更改成功、终止及任务筛选规则 |
| 固定实验协议 | 三人共同冻结，C 登记 | 变更必须形成新协议版本，不能追溯修改已运行实验 |

A0 由 A 训练，C 核验并评估，B0 直接引用相同权重。B 不等待 A 的最佳候选，也不把 A 的所有结构再与 H/E 做全组合。当前根目录中的训练与仿真入口保持可用。

## 里程碑

1. **协议冻结**：核对输入信息、数据版本、预算、种子和指标；C 划定开发/最终评测清单，A/B 确认张量合同。
2. **独立开发**：A 实现单步变体；B 审计数据连续性并实现序列；C 跑通原 AeroVLA 和现有扩散评估，搭建统计。
3. **小规模交付**：A/B 各提交一个可重载的小模型流程检查；C 验证统一加载和闭环接口。
4. **正式训练和评估**：A/B 提交冻结权重与清单；C 对通过检查的权重执行同任务正式评估。
5. **复核与报告**：关键对照重复训练/推理，按任务 UUID 配对；A/B 解释方法结果，C 汇总表格和失败分析。

先完成同种子探索，再对关键对照执行种子 42、43、44 的独立训练；不能把同一权重的不同采样种子称为独立训练重复。H/E、注意力和采样随机性都需记录。

## 交付包

每次交付包含 checkpoint 目录、代码版本、配置、数据/划分标识、随机种子、训练预算、离线结果、最小加载命令和已知限制。采用[运行记录模板](../../evaluation/course/run_manifest.example.json)。C 先检查加载、配置、数据和短程闭环，再运行正式任务。

各自负责的方法必须由各自撰写；C 负责整体实验设置与结果汇总，不承担全部报告写作。原 AeroVLA 与课程前扩散实现列为基础，新增贡献单独声明。
