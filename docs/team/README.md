# 三人均衡推理测试分工

只调用已有评估入口，使用全部已训练正式权重，不再训练、不修改代码或框架。取消原来的输入扰动、多候选选择、去噪 hook、原 token 离线适配和新运行器开发。扩散固定 DDPM/100/10，H=1、E=1；不做扩散步数实验。

## 三人执行相同类型的任务

| 成员 | 离线测试 | 闭环测试 | 自己的交付 |
| --- | --- | --- | --- |
| [A](member_a.md) | 登记给 A 的 8 个扩散状态；另负责原 AeroVLA 参考模型资源核对 | 自己约 1/3 的任务，运行全部五个代表模型 | 指标表、成功/失败案例、个人报告部分 |
| [B](member_b.md) | 登记给 B 的 9 个扩散状态 | 自己约 1/3 的任务，运行全部五个代表模型 | 指标表、成功/失败案例、个人报告部分 |
| [C](member_c.md) | 登记给 C 的 9 个扩散状态 | 自己约 1/3 的任务，运行全部五个代表模型 | 指标表、成功/失败案例、个人报告部分 |

[模型清单](../../configs/course/models.json)的 evaluation_owner 标明负责人。27 项登记中有 26 个扩散状态与 1 个原 token 模型；现有离线入口只支持扩散，所以原 AeroVLA 仅参加闭环，离线指标写“不适用”，不开发适配器。offline_owner 旧字段仅为兼容保留。

五个闭环代表为原 AeroVLA、扩散头 best、联合初始化 step 0、联合 step 1000、联合 final。其余联合中间检查点通过离线测试覆盖。联合 best 是 step 0 对照，smoke 不进入性能比较。

## 独立执行与工作量

三人预先把现有闭环任务按长度/地图划为三份，通过已有 TEST_JSON 参数指定清单；同一人的五个模型必须使用相同任务和顺序。不改变任务内容、模型输入、控制器、停止规则或推理策略。各自使用独立结果目录；同时运行时使用各自独立的服务与端口，资源不足则排队。

每人完成自己的加载核对、离线、闭环、已有指标统计和案例说明，不安排专人替其他人跑全部评测或写报告。A 少一个扩散离线状态，以原参考模型的资源核对补充；先小规模验证加载/运行时间，再按预计仿真耗时微调任务分片，使三人工作量接近。调整必须在正式评测前完成，不能按成功率重新分配。

不安排各人独立的新算法。公共工作只包括一起确认任务清单、合并既有结果表和交叉检查记录；不增加公共模块或开发接口。

## 执行与交付

1. 按[指南](../guides/training_and_evaluation.md)核对现有资源和 checkpoint 路径，固定任务、输出目录和环境。
2. 各自调用 `scripts/eval_diffusion_head.sh` 完成分配的扩散离线测试。
3. 各自调用 `scripts/eval_aerovla.sh` 完成五模型在自己分片的标准闭环测试。
4. 使用 `utils/metric.py` 和现有输出，记录动作误差、LAND 指标、SR/OSR/SPL、完成/失败任务；各写成功与失败案例。
5. 合并逐任务结果后再统计总指标，不平均不同大小分片的百分比。每人提交原始结果路径、命令、指标表、案例和个人报告。

现有在线 RNG 随进程/任务顺序消费，本方案不声称实现了 episode 级配对随机噪声；任务和结果按 UUID 配对即可。多 seed 闭环、细粒度延迟计时和去噪内部记录均不安排。
