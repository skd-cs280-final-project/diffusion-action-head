# 三人均衡推理实验分工

本阶段使用已有权重，不再训练。A/B/C 各自负责独立研究线，并完成本线的代码、离线、闭环、统计、图表和写作。固定扩散配置为 DDPM/100/10，动作 H=1、E=1。

## 模型覆盖与共同基准

[模型清单](../../configs/course/models.json)登记 27 个状态：原 AeroVLA、仅头 best、联合 step 0、23 个中间检查点、final。step 0 只是初始化对照，smoke 权重不作为性能基线。

- **S0 全模型离线**：按 models.json 的 offline_owner 分为每人 9 个；相同固定 val 和指标，结果通过共同格式合并。原 AeroVLA 无 noise MSE，不能填 0。
- **S1 共同闭环**：五个预先指定模型在相同任务/种子上评估。将任务 UUID 按长度/难度分层后划为 A/B/C 三份，每人对自己的任务跑全部五个模型，任务不重叠、不遗漏。各模型的分片清单完全相同。
- **本线闭环**：每人自己运行自己选定的正式条件，不能全部交 C。先冻结一个代表条件，试跑核算后最多扩至三个；使用相同最终任务集合。
- 原始观测、标准模型结果和原始日志只生成一次，三人共享引用。图像/条件缓存必须按权重、输入和预处理版本区分，联合模型之间不能复用错误特征。

这里的“全部模型”指全部登记状态至少有离线结果；不要求 27 个模型乘以全部扰动、策略、种子做闭环。细化变体使用五个代表模型，其中采样相关实验只适用于四个扩散代表。

## 工作量均衡

每人交付：9 个 checkpoint 的共同离线评估、约 1/3 的五模型共同闭环、本线 3 类离线分析、预先冻结的 1–3 个本线闭环条件、至少 3 张分析图、1 个失败案例集及自己的章节。

计算量不按配置个数机械平均。先对共同开发任务试跑，记录 GPU 小时、仿真小时、wall time 和开发工时。多候选策略更贵、某些长任务更慢时，可重新分配整块任务 shard 或减少本线正式条件，使三人的预计实验资源和实施工作接近；在正式开始前登记分配，不能根据成功/失败结果转移任务。

## 公共工作也分摊

| 公共任务 | 初始负责人 | 边界 |
| --- | --- | --- |
| checkpoint 预检、采样 seed/去噪 hook 适配 | A | 不改网络或权重；提供通用采样入口给 C |
| 固定观测/任务清单、开发与最终分片 | B | 不按方法效果挑任务；负责输入变换隔离 |
| 指标 JSON/CSV、任务配对与计时合同 | C | 提供轻量公共函数，不代跑全部实验或代写全部报告 |

原 AeroVLA 的共同离线动作适配由对应 S0 负责人实现并通过公共 schema 核对。各自使用独立输出目录、仿真端口和日志；公共 wrapper 的小改动先登记，由 A 合并接口，业务逻辑留各自目录。

## 交付顺序

1. 三人共同冻结协议、五个代表模型、输入与随机种子方案；A/B/C 分别完成公共准备。
2. 各自对本线一个小例子验证，提交统一记录；不等待其他研究线的“最佳结果”。
3. 完成每人 9 个 checkpoint 的 S0；共同 S1 分片并行进行。
4. 本线离线分析选出预先约定数量的正式条件，在开发集固定参数，再各自完成闭环。
5. 每人汇总自己结果、写方法与局限；共同合并主表，交叉复核另一人的 1 个运行包。

重复的是推理随机性，不是独立训练。中间 checkpoints 属于同一训练轨迹；头 best 到 joint final 的差异还包含额外训练预算。所有新结果必须绑定 checkpoint 哈希、配置和任务清单。
