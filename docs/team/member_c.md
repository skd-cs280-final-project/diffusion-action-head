# 成员 C 评估复现与结果分析

[团队总览](README.md) · [实验协议](../experiments/protocol.md)

C 从项目开始建设评估体系，不等待 A/B 正式权重。使用现有扩散模型和原 AeroVLA 验证端到端流程；不承担新增动作头研发。

## 工作顺序

1. 固定开发与正式任务清单，保存 UUID、排序、数据来源和随机种子；核查既有任务是否参与过调参。
2. 复现原 AeroVLA（C0，参考基线）和已有扩散权重的评估。历史权重与课程新训练权重在表格中分开。
3. 在 `evaluation/course/` 实现模型无关的结果记录、校验、任务配对、统计及图表；现有离线评估器专用于扩散，不能假装已支持 A1。
4. 验证 A/B 的小规模交付，随后执行正式闭环和必要的重复评估。
5. 汇总共同成功、共同失败、从失败转成功和从成功转失败；产出主表、成本图和失败案例。

## 指标与统计

- 离线：共同第一步 fwd/down/yaw MAE、RMSE、归一化 MSE，LAND TP/TN/FP/FN、P/R/F1、正例数量；多步额外报告各位置误差。
- 闭环：SR、OSR、原协议 SPL、最终目标距离、参考终点距离、完成数量和总分母。
- 计算：固定硬件与测量方式，预热后同步计时，分别报告骨干、头、端到端平均/P95，记录显存、参数量和模型调用次数。
- 失败：物理接触与深度近障分开；保留原终止规则，分类可以细化，判定不能悄悄改变。
- 配对：同一 UUID / 场景 / 初始条件，按任务或轨迹为统计单位；帧不是独立任务。重复推理嵌套在同一任务内，不能简单增加独立样本数。

当前 `utils/metric.py` 的 NE 实际为参考终点欧氏距离，SPL 的参考路径长度减去 20，须标注原协议。当前方向提示使用目标位置信息，各模型保持一致并披露。

## 完成标准

无重复 UUID、不将未完成任务算作普通失败、不用开发任务宣称全新测试泛化；所有结果追溯到配置、权重和原始日志。每个新模型先做加载和小规模闭环检查。产出可重新生成的表格/图、运行清单、统计说明与演示视频。参考[运行记录模板](../../evaluation/course/run_manifest.example.json)。
